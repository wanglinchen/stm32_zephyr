STM32 上的 Zephyr 分层架构

01

分层与依赖方向

向下单向依赖：上层只调标准 API，绝不越过设备抽象层直接操作 STM32 HAL。硬件事实只存在于 devicetree 与 Kconfig 两处。

L4 应用层
业务线程 / 状态机 / 命令处理
app/src/*.c · app/include/app_*.h
心跳线程、采样处理线程、Shell 命令组。只依赖标准 API 与自身头文件，不知道引脚号。
L3 服务层
日志 / Shell / 设置 / 文件系统 / 电源管理
zephyr/subsys/{logging,shell,settings,fs,pm}
按需裁剪。日志采用延迟模式，中断里只入缓冲，由日志线程落串口。
L2 内核层
调度 · 线程 · 信号量 · 消息队列 · 定时器 · 内存池
zephyr/kernel/
抢占式优先级调度；中断到线程通过 k_msgq / k_sem 交接；共享数据用 k_spinlock 保护。
L1 设备抽象
设备模型 · 驱动 API · pinctrl · clock_control
zephyr/include/zephyr/drivers · zephyr/drivers/
gpio / serial / i2c / spi / adc / pwm / watchdog … 统一 device 结构与 API，板级差异由 dts 传入。
L0 架构与 SoC
Cortex-M 异常与上下文切换 · STM32F4 SoC 初始化 · HAL/LL · CMSIS
arch/arm/core/cortex_m · soc/st/stm32/stm32f4x · modules/hal/stm32 · cmsis_6
复位入口、PendSV 切换、FPU 上下文、时钟树配置、外设寄存器定义。此层以下是芯片。
HW
STM32F429ZIT6 + 板载外设
Flash 2MB @0x0800_0000 · SRAM 192KB @0x2000_0000 · CCM 64KB @0x1000_0000
LD3 PG13 / LD4 PG14 / 按键 PA0 / I2C3 触摸 / SPI5+LTDC 显示 / FMC SDRAM。
02

存储器映射

数值取自 zephyr/dts/arm/st/f4/stm32f429Xi.dtsi 与板级 dts。条形长度为定性示意，标注容量为准。

0x0800_0000
Flash · flash0
代码段、只读数据、向量表；zephyr,flash 指向此处
2 MB
0x2000_0000
SRAM · sram0
SRAM1 112KB + SRAM2 16KB + SRAM3 64KB 连续映射；.data / .bss / 线程栈 / 堆
192 KB
0x1000_0000
CCM RAM · ccm0
CPU 零等待访问；zephyr,dtcm 指向此处，适合高频热数据
64 KB
0xD000_0000
SDRAM · sdram2（FMC）
外部显存，LTDC 帧缓冲；以 zephyr,memory-region 暴露给驱动
8 MB
CCM 的硬约束：CCM 挂在 CPU 私有总线上，DMA 控制器访问不到。任何 SPI/I2C/ADC 的 DMA 缓冲若放进 CCM，会表现为“传输完成但数据全 0”的静默故障。
03

启动与初始化级别

五个初始化级别决定了“这段代码运行时，哪些内核能力已经可用”。错用级别最常见的结果是驱动在时钟未就绪时 probe。

Reset_Handlerarch/arm/core/cortex_m
关中断、建立最小运行环境，调用 SystemInit() 完成 FPU 使能与向量表基址设置。
z_cstart()C 运行时入口
拷贝 .data、清零 .bss、初始化 CCM 段、建立中断栈与主线程栈，随后切换到主线程上下文。
EARLY极早期
仅能访问寄存器，用于看门狗、极早期时钟；本工程不使用。
PRE_KERNEL_1 / PRE_KERNEL_2内核尚未调度
中断可用但内核对象不可用；时钟控制、串口底层、GPIO/pinmux 在此完成。
POST_KERNEL内核已运行
大多数驱动的 device_init 在此执行：设备结构注册完成，可安全使用信号量与队列。
APPLICATION → main()应用入口
业务初始化显式写在 main()：先自检驱动句柄，再拉起线程，最后进入低频巡检循环。
04

中断到线程的数据通路

实时性来自边界划分，而不是更快的 CPU：中断只做搬运，计算全部下沉。

注：本节的 app_sensor 采样链路当前已从应用移除（源码备份于 build/_sensor_backup_20261115），本节保留作为中断→线程通路的参考设计。

k_timer 到期（ISR 上下文）

读取一次采样值，k_msgq_put(&q, &v, K_NO_WAIT)。队列满就丢弃最新样本，绝不等待。

▼ 环形缓冲，深度 64，样本 10ms 一个

sensor_proc 线程（优先级 8）

k_msgq_get(K_FOREVER) 阻塞取样本，做一阶 IIR 滤波与 min/max/avg 统计，临界区用 k_spinlock。

▼ 快照读取，无锁竞争

main 线程 / Shell

每 5 秒打印一次统计；app stats 命令随时查询。日志走延迟模式，不阻塞上述任何一方。

05

构建流水线

一条命令背后是五段职责：工作区解析、Kconfig 求解、devicetree 生成、编译、链接与烧录。

01
west 工作区
读 .west/config 定位 manifest，解析 west.yml 与模块路径。
02
CMake 配置
确定 board → SoC → arch，探测工具链与 SDK 版本。
03
Kconfig + DTS
求解 .config；把 dts/overlay 展开成 devicetree_generated.h。
04
编译 · 链接
Ninja 编译；链接脚本按 dts 内存节点自动生成。
05
烧录 · 观测
west flash（pyocd / ST-Link）；-t ram_report 查占用。
06

配置职责边界

谁能改什么，写清楚才不会出现“应用代码里硬编码引脚”的返工。

层级文件职责与禁止项
应用能力app/prj.conf功能开关：LOG、SHELL、协议栈。禁止出现引脚、外设地址、板名。
板级差异app/boards/*.conf板特有开关（如显示、外部存储）。禁止写业务逻辑开关。
硬件描述app/boards/*.overlay引脚复用、外设状态、时钟参数。禁止定义应用数据结构。
上游默认zephyr/soc/**/Kconfig.defconfig只读参考，不在上游目录内改；需要覆盖就在 overlay / conf 里改。
